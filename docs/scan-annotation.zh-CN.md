# `charloom mh-transfer` 指导（视觉代理任务）

[English](scan-annotation.md) · 简体中文

当前版本使用Python指南的CLI。请使用源代码GLB和来自仓库根目录的指南路径来运行它。以下注释字段适用于此路径。在旧章节中对`charloom mh-*`命令的引用指的是已弃用的CLI。

| 操作 | 当前命令 |
| --- | --- |
| 新校准视图 | `"$PY" scripts/scan-guide.py "$SCAN" --out "$GUIDE"` |
| 面部特写 | `"$PY" scripts/scan-guide.py "$SCAN" --refine "$GUIDE/guidance.json"` |
| 像素盒特写 | `"$PY" scripts/scan-guide.py "$SCAN" --zoom "$GUIDE/guidance.json" --view VIEW --box X0 Y0 X1 Y1 --name NAME` |
| 唇部接缝 | `"$PY" scripts/scan-guide.py "$SCAN" --trace "$GUIDE/guidance.json" --view VIEW --pixels POINTS.json --output "$GUIDE/mouth-trace.json"` |
| 验证与解决 | `"$PY" scripts/scan-guide.py "$SCAN" --check "$GUIDE/guidance.json"` |

对于运行设置，请使用 [环境说明](../skills/charloom/references/setup.zh-CN.md)。


您正在查看一个生成的3D角色的正字渲染图。您的答案会指导一个数值流程，将其转化为适用于MakeHuman的角色：服装和头发被切割成单独的网格，MakeHuman的躯干被适配在下方，而面部则根据您的标志点进行对齐。

将文件夹中的 `guidance.template.json` 复制到 `guidance.json` 并填充它。仅回答你能看到的内容。每个坐标都是 **命名视图图像中的像素**，`[x, y]`，原点位于左上角。`-grid.png` 图像每 50 px 有一个标尺（每 100 px 有一个标签）；纯 `.png` 图像没有网格，但结构相同。

视角（`views.json`表示具体的摄像机位置）：

| ID | 它所展示的内容 |
| --- | --- |
| `body_y000`, `body_y090`, `body_y180`, `body_y270` | 全身，摄像机围绕垂直轴以0/90/180/270°的角度旋转 |
| `head_y000` … `head_y270` | 来自相同四个方向的模型的前15%部分（头部） |
| `face_*` | 由 `charloom mh-guide-refine` 添加的面部特写镜头（第3节） |
| `zoom_*` | 您所要求的 `charloom mh-guide-zoom` 特写镜头（第7节） |

## 1. `front_view`

角色面向你的身体视角，例如 `"body_y000"`。下方的“左/右”指的是**角色自身的**左右方向：在正面视角中，角色的左边位于图像的右侧。

## 2. `subject`

`kind`: 使用`human`或`stylized_humanoid`（大头，卡通比例）或`nonhuman`。`sex`: 使用`female`/`male`/`unknown`（选择MakeHuman的基础模型）。`notes`：任何不寻常的元素（尾巴、翅膀、额外的肢体、手中所持的道具）。可选的`subject.head`用于控制基础模型的转换。默认的`fit`适合MakeHuman的头部和骨骼结构。对于刚性头部，`keep_scan`会将纹理扫描图连接到头骨上，并且需要暴露的颈部接缝。运行配置可以覆盖此字段。最终组装时，可以将原始扫描头与适配的身体结合。

`hand_digits`（可选，2–5，以拇指计数）：当每只手不是五指时，每根手指有多少节——`4`表示拇指和三个手指，`3`表示拇指和两个手指，`2`表示拇指和一个手指（MakeHuman的手指分布在手掌上：食指、中指和小指；食指和小指；中指）。两只手各一个数字，或者当它们不同时，用`{"l": 4, "r": 5}`表示。以每只手的特写方式计数（爪子不算数字；手腕上的外副乳也不算数字）。MakeHuman的多余手指被排除在外，并从输出结果中去除；手的手指数量从拇指开始依次排列。如果是五指，则省略此数字。

`proportions`（可选）：身体与人体比例相差多少——`human`（任何真实人物，从瘦到非常肥胖），`stylized`（动漫或游戏中的英雄角色：比普通人更长的腿、更大的胸部或更细的腰，但仍属于人类形象），或`extreme`（现实中不存在的卡通形象：巨大的腹部搭配短粗的腿，头部是身高的三分之一，手臂像桶一样粗）。这个参数决定了身体在MakeHuman模型中的活动范围；不必要的`extreme`会导致测量误差，因此选择最少的数值即可。如果不需要这个参数，则省略`human`；如果使用的是人类模型，则使用`stylized`。

### 选择动画头部路径

对于每个新的动画面部，都使用原始的纹理扫描头。在基础转移过程中使用`fit`来准备身体和骨骼结构，然后从扫描转移中组装`volume`头部。体积构建器会保留原始头部的三角形结构及其在新的嘴巴和眼睛周围的纹理。

检查有纹理的前部、斜侧和侧面。确定哪些眼睛、眼睑、睫毛、牙齿和舌头具有各自的几何形状。将这些观察结果以及校准后的视图记录在`subject.notes`中。将已审核的三角形范围与当前扫描结果相关联，用于区分不同的面部部分。标记出实际的眼睛开口和嘴巴，包括已绘制的部分。保留带有唇痕的扫描和视图。对于突出的口鼻部，检查上唇下方的下颌。

关注 [面部和对话技能](../skills/charloom-face-dialogue/SKILL.zh-CN.md) 以获取组装和播放信息。将中性侧脸与原始图片进行比较，闭上双眼，改变注视角度，并在裸体及穿着后的导出图片中播放对话。检查下巴和牙齿在张开时的状态，以及通过头部转动展示的颈部。记录任何未解决的问题特征。

## 3. `landmarks`

名称 → 观测列表 `{"view": id, "px": [x, y], "confidence": c, "visibility": v, "reason": "…"}`。一个观测点就足够了。对于关节和手部点，至少需要从15°夹角以上的两个视角进行观测（正面和侧面），并进行三角测量，这样会更准确；来自几乎相同方向的两个观测点则视为一个，因为它们没有深度信息。表面点（面部）则分别放置在皮肤上，并进行平均处理，因此只需在能清晰看到这些点的最清晰视角下标记一次（`face_*`或`zoom_*`）。无法看到的部分则省略不记。

`visibility`（可选）：`visible`、`partial`（一条带子、袖口或带子覆盖部分位置）或`occluded`（隐藏在衣物或头发下，根据比例放置）。`occluded`将置信度减半，`partial`保留80%的置信度。`reason`（可选）：说明为什么需要这个位置或什么隐藏了它（“在袖子下面，根据比例”）；用于后期审查。

`confidence` (0–1，默认值为1)：您对某个部位的确定程度。如果非常确定，使用1；如果部分可见，使用0.5；如果部位被靴子或紧身袖子遮住，使用0.2–0.4。对于被宽松衣物遮盖的关节（如斗篷或束衫下的髋部、宽松裤子中的膝盖），使用0.2–0.4。对于不确定性的关节，只需稍微调整比例；具体数值由几何形状决定。

面部（表面点数，使用`head_*`视图；点击确切位置）：`eye_l`、`eye_r`（瞳孔/虹膜中心；对于画着眼睛或闭着眼睛的情况，为眼睛开口的中心），`nose_tip`、`mouth_l`、`mouth_r`（嘴角）。

表面点**位于皮肤表面**，而不是位于像素下方的第一个表面：渲染管线会经过头发/衣物多边形中的表面，也会经过距离相机较近的层次，而不是仅经过皮肤点（如松散的线状物）附近的皮肤。如果后面没有皮肤，该点将被**排除**（作为检查中的错误）。不过，仍然需要标记可见的皮肤：眼睛角前面的线状物会隐藏眼睛角的真实位置。

眼睛开口（第二次处理）：在保存`guidance.json`后，运行`charloom mh-guide-refine guidance.json`。它会添加以面部为中心的`face_y000`、`face_l35`、`face_r35`特写视图。在`face_y000`标记中，每只眼睛的`eye_l_inner` / `eye_l_outer`（眼睑相接的角落）、`eye_l_top` / `eye_l_bottom`（瞳孔上下方的眼睑边缘），以及相同的标记适用于`eye_r_*`。您也可以重新标记`eye_l`、`eye_r`、`nose_tip`、`mouth_l`、`mouth_r`，以追求精确性；替换头部视图中的观察结果，而不是添加冲突的信息。眼睛开口决定了MakeHuman眼球的尺寸，以及扫描的眼线和平坦的眼睑的位置。

眼睑边缘（可选；当眼睛睁开且眼睑可见时标记）：每只眼睛的**眼睑边缘**上记六点，即眼睑与眼球相接的边缘（即眼线或眼线笔的内缘，白色部分或虹膜开始的位置），而非眼线笔的外缘、眼眉的翼部或眼眉的尖端。
- 在上眼睑上，距离内眼角（从鼻子方向）到外眼角约25%、50%和75%的位置，分别有`eye_l_upper_1`、`eye_l_upper_2`和`eye_l_upper_3`；
- `eye_l_lower_1`、`eye_l_lower_2`、`eye_l_lower_3`在下眼睑上相同；
- 对于`eye_r_*`来说也是同样的规则（`l`/`r`代表角色的面部特征，如眼角部分）。它们将MakeHuman的眼睑曲线固定在四个开口点之间。在`face_y000`中标记这些点，或者在每只眼睛的特写视图中更清晰地标记（`charloom mh-guide-zoom guidance.json --landmark eye_l`，然后在`zoom_eye_l`中标记；`zoom_eye_l_o30`视图会朝向外眼角，能够更清晰地显示眼睑的边缘）。与其他面部特征点一样，这些点被放置在皮肤的下方，每个视角都足够了，第二视角会进行平均处理。标记出每只眼睛的六个点，或者没有标记；对于闭合或隐藏的眼睛则忽略这些点。如果眼睑的某些点没有按照从内眼角到外眼角的顺序排列，或者上侧的点不在下侧的点之上，或者某个点超出了开口的边界，或者左右位置颠倒了，系统会发出警告。其叠加图会在每个可见的视角中显示每个眼睑的轮廓（内眼角、1、2、3，外眼角），并且在斜向视角中也要遵循眼睑的边界。

耳朵轮廓（可选；当耳朵至少部分可见时标记）：在显示耳朵的侧面头部视图中，在**可见**的耳朵上标记点（`head_y090` / `head_y270`，或你的`front_view`的侧面视图），在每只耳朵的特写视图中更清晰（`charloom mh-guide-zoom guidance.json --box head_y090 X0 Y0 X1 Y1`在耳朵周围，或`--landmark ear_l`在标记一个ear_point时）。每只耳朵（`l`/`r`角色）：
- `ear_l_top`：螺旋形结构的最高点（边缘）；
- `ear_l_back`：螺旋的最末端；
- `ear_l_lobe`：叶子的底部；
- `ear_l_front_top`：即耳朵顶部与头部连接的部位，位于耳垂（即耳轮的基部）上方；
- `ear_l_front_bottom`：即 lobe 与头部连接的部位（脸颊或下颌）；
- `ear_l_tragus`：耳垂的尖端，即耳道前的那个小褶皱。标记**仅标注你能看到的部分**：省略所有被头发、一缕头发、帽子或衣物遮盖的点（MakeHuman的默认耳朵形状会填充这些隐藏部分），并且永远不要将一缕头发的边缘标记为耳廓。放置耳朵至少需要两个点；三个或更多点才能形成正确的形状。MakeHuman的耳朵是根据这些点进行放置、缩放和塑形的（其默认耳朵目标也是基于这些点），而扫描得到的耳朵颜色只会在它们绘制的轮廓内呈现，因此生成的耳朵不会在头部上重复绘制。如果点的位置顺序错误（如顶部不是最高的，耳垂不是最下方的，后侧不是最靠后的，前侧的点不在后侧的前方），或者耳朵的尺寸或位置不合理，或者两只耳朵的差别太大，系统会发出警告。其叠加图会显示每只耳朵的清晰轮廓（橙色，从前面到顶部闭合，从后侧到耳垂都是如此）。

身体关节（从该视角看到的关节中心；仅在一个视角下使用两个图像坐标，深度来自沿观察线的横截面探头——即肢体中间，或你标记的衣服下的身体层——以及从贴合度）：`neck`（颈部基底，位于下颌之间），`shoulder_l/_r`（肩关节，非肩部顶部），`elbow_l/_r`，`wrist_l/_r`，`hip_l/_r`（髋关节，大致位于腿部折痕处），`knee_l/_r`，`ankle_l/_r`。在衣服下面，根据身体比例来估算关节的位置，而不是根据衣服本身的形状：
- **髋部。**髋关节位于腿部皱褶处，距离腰部约一掌宽。腰带或束带位于腰部，位于髋部上方。对于成年人来说，髋部大约占站立高度的一半。
- **膝盖。** 每个膝盖位于髋关节和踝关节之间的中间位置。宽松的裤子或睡袍的下摆不会移动膝盖。
- **肘部。**每个肘部位于从肩部到腕部之间的手臂长度上，大约处于一半的位置。袖口或护腕边缘不会标记该位置。

在侧视图中标记每个关节（`body_y090` / `body_y270`），特别是在明显可见的位置（如裸露的肘部、膝盖或脚踝）；如果仅在一个视图中看到某个关节，请标记为“检查警告”。如果侧视图中无法显示某个关节（如领口下的颈部、斗篷下的髋部），则将其标记为“单视图”：如果猜测的侧视图能够显示该关节，则将其标记为“深度”，如果仅有一个视图，则将其标记为“几何形状”。

在修改身体服装和MediaPipe身体关节后，手会被测量，而不是标记：`out/tools/cv/.venv/bin/python -I scripts/mh-hand-landmarks.py --write GUIDE_DIR`会为每个手制作一组特写镜头，通过三角测量MediaPipe的21个手部点，计算扫描表面上的手指数量，并写入`subject.hand_digits`、`subject.hands`（对于五个手指，`fit`表示其点形成的手形，否则使用`keep_scan`：扫描自己的手，保留并映射到MakeHuman的骨骼中）以及手指和手掌的标记。只有在没有手被报告的情况下，才会标记手。

手（可选，但很有用：它们将MakeHuman的手指骨骼映射到扫描仪的手指上）。在每只手的特写中标记它们（第7节，`--box`部分，在身体视图中看到手的背面或手掌时，而不是从侧面观察）。名称：`finger{F}_{S}_{P}`
- `F` = 拇指1次，食指2次，中指3次，无名指4次，小指5次；
- `S` = `l` / `r`，角色的侧面；
- `P` = `base`：手指离开手掌处的关节点（对于拇指来说，是拇指与食指之间的连接处）；`mid`：中间关节点（手指：第二个关节点；拇指：唯一可见的关节点）；`tip`：手指的末端，靠近指甲的位置；
- 加号 `palm_l`, `palm_r`：手掌中心（或手背中心）。

在手指的中央标记其宽度，就像在关节处那样：深度是指手指沿观察方向的中央位置。隐藏在另一个手指后面的手指可以省略；对于融合或类似手套的卡通手指，只需标记出可以区分的手指。当`subject.hand_digits`小于5时，将手的手指编号，从拇指开始（`1`为拇指，然后是`2`、`3`……以此类推），并省略较大的数字：在拇指加三个手指的手中，最外侧的手指为`finger4`，而并不使用`finger5`。在第二个特写视图中，至少15°的距离处，也标记相同的名称（即`_o30`），当手指清晰可见时。

**身体轮廓**（在衣服遮盖身体形状时推荐标注）：在每个位置，根据您判断的**身体边缘**来标记，而不是衣服的边缘。在紧身衣服下，是衣服的边缘；在宽松衣服、长袍、盔甲或从背部垂下的衬衫下，则是皮肤所在的位置（即布料垂挂的轮廓、腹部、胸部和臀部的曲线）。身体的大小及其前后位置与这些标记相对应；如果没有这些标记，则需要根据衣服的表面来推测。
- 位置：`chest`（在乳房或乳头处），`waist`（躯干最窄处），`hips`（臀部最宽处），每侧还有`upperarm_l/_r`（上臂中部分）、`forearm_l/_r`（前臂中部分）、`thigh_l/_r`（大腿中部分）、`knee_l/_r`、`shin_l/_r`（小腿中部分）以及`skull`（头骨在耳朵上方的宽度和深度，位于头发下方：仅能判断头皮线的位置）；`scripts/mh-bodysuit.py`则采用剃光头模型进行测量。
- 在**前**身体视图中，`outline_{station}_w1`和`_w2`：该身体部位的左右边缘（无论顺序如何），横跨该部位（对于四肢，是横跨四肢，而非水平方向）。
- 在身体的**侧视图**上，用 `outline_{station}_d1` 和 `_d2` 标出前、后边界。测肢体时选能看清对应侧的视图。例如，当 `front_view` 为 `body_y000` 时，`body_y090` 显示角色左侧。
- 同一视图中一对边的两个边缘；孤立的边界被忽略。只标记你能判断出的边界（被另一个边界隐藏的边界被遗漏）；置信度表示你对隐藏边界的确定程度（在宽松的布料下为0.4–0.6，对于可见或紧密的边界为0.8–1）。

**身体套装轮廓**（已测量，未标记）：`scripts/mh-bodysuit.py --edit --write` 的图像模型需要重新绘制前视图和侧视图，使用的是紧身绿色套装，头部被剃光。`scripts/mh-suit-contours.py` 将这一编辑的轮廓修改为`views/suit_contours.json`。然后`scripts/mh-suit-ensemble.py --edit` 要求再进行三次编辑，并写入`views/suit_contours.ensemble.json`（默认的合身度，Config `suit_contours_file`）：每个视图对应一个共识轮廓，每个点的权重取决于编辑内容在哪些地方一致。如果编辑内容在所有地方都不一致（超过3像素），则采用单一编辑结果。

## 4. `garments`

每个单独穿戴的物品都有一个单独的网格，包括头发和头饰：

```json
{"name": "robe", "label": "garment", "layer": 1, "tight": false,
 "regions": [{"view": "body_y000", "polygon": [[x,y], [x,y], ...]},
             {"view": "body_y180", "polygon": [...]}]}
```

- `label`: `garment`或`hair`（假发、辫子、发髻、发带、发簪：`hair`）。
- **头部视图也要标头发。** 头部视图分辨率更高，用来确定发际线。在能看到头发的每张 `head_*` 视图上标出发区，包括刘海和垂到额头、太阳穴、面颊或颈部的散发。
- **肤色发丝。** 扫描中耳旁、脸颊前和颈部的松散发丝可能被涂成肤色，有时只有发梢如此。在每张 `head_*` 和 `face_*` 视图里按细长、从头发垂下的几何形状辨认。沿每根发丝画同宽笔划，归入头发。流程也会寻找悬在皮肤前或从头发垂下的细面，旧版 `mh-guide-check` 以洋红表示将并入头发，以青色表示保留为皮肤的悬浮薄层。两类都要检查。贴在皮肤上或融入其中的发丝需要手工标记。耳缘误标洋红时用 `skin_strokes` 沿边缘画一笔，皮肤笔划会保留原分类。画在皮肤上的胡须、眉毛和睫毛仍归入皮肤。
- `layer`：0表示附着在皮肤上（如衬衫、裤子、鞋子）；1表示覆盖在那些之上（如长袍、背心、盔甲）；2表示覆盖在那些之上（如斗篷），以此类推；根据服装的层次，可以使用多个标记。
- `tight`: 适用于紧密贴合的物品（如T恤、打底裤、手套）。
- `gap_mm`（可选）：皮肤在物品外表面（材料加上空气）中的嵌入程度，以毫米为单位。对于贴身衣物，数值为几毫米；对于宽松的连衣裙，数值为15–30毫米；对于长袍或覆盖在其他层上的盔甲，数值为40–70毫米。隐藏的躯干、手臂和腿部则填充到物品表面，减去这个间隙。如果袖口或下摆露出皮肤，则在此处测量间隙；如果没有这些部分，则采用`tight`和`layer`的默认值。
- `regions`：在可见的任何视图中，项目**内部**绘制的多边形，最多到其边缘。每个多边形的种子会在连接的表面上**生长**，直到颜色发生变化（在該视图中最多约24像素）。因此，距离边缘几像素远的多边形仍然会覆盖该项目，两个多边形之间的表面会过渡到颜色与之匹配的那个多边形。多边形会将其标签绘制到其深入的位置（≥ 8像素），在该位置颜色会与项目匹配，并且会绘制到其生长到的所有地方；靠近边缘的非彩色像素（面多边形的边缘线）只会选择显示为头发或衣物。当多边形重叠时，较小的多边形会占据优势（在真实大小上，跨多个视图；包括皮肤多边形和笔触）。因此，可以自由地绘制较小的项目（如发夹、腰带）在较大的项目上，而面部皮肤多边形在头发轮廓内仍保持皮肤效果。必须绘制每个可见的侧面（至少正面和背面）；未标记的衣物部分会从最近的标记项目填充；未标记的裸露皮肤可能会成为额外的部分，因此必须标记所有裸露皮肤。
- **颈部线。**上衣的多边形在领口处结束：裸露的颈部以及V领内部或交叉的翻领之间的皮肤属于皮肤部分（在皮肤多边形中标记），绝不属于衬衫的多边形部分。明显显示皮肤的多边形不会强制到服装上，但错误的多边形仍会导致边界不稳定。在颈部周围，皮肤/服装的边界在大约2厘米范围内与领口的折痕或颜色边缘对齐，因此绘制到领口的多边形就足够了。如果领口的颜色接近皮肤颜色（如浅色皮肤的乳白或白色），而分割线仍然将边界放在错误的位置，则需要在领口带（其自身宽度）上添加一条线：线条会保持其标签。
- `rigid`（可选，默认值为false）：附着在身体上的硬部件，不得弯曲——如爪子、角、象牙、喙尖、鹿角、尖刺、角环。每个连接的部件都遵循主导身体的单一骨骼，例如在手指的末端，爪子与手指的最后一节骨骼相连；角与脚趾相连；角与头部相连。这些部件保持其原始形状，而不是混合布料的重量。为爪子、角和象牙赋予独立的物品（如`"label": "garment"`，例如`claws`、`horns`），而不是让它们保持无标记状态：无标记的暗色爪子最终会附着在最近的衣物上，并飘离手指。小爪子可以用线条标记，每条爪子都带有一条短带。
- 将需要单独附件的每个物理区域标为独立项。在头盔上，勾勒出外壳，并在松散的系带处画上单独的线条。在连衣裙上，分别标记出合身的衣身和自由裙摆。检查正面、侧面和背面视图，以确定系带或腰带的位置。
- `rig` 用于选择该物品的多边形和笔触的绑定方式。精确的物品名称 `helmet`、`skirt` 和 `ribbon` 在旧版指南中提供默认设置。如果明确指定，则优先使用该方式。使用 `{"mode":"body"}` 表示需要紧密贴合的布料，包括缝制在上面的丝带或印刷图案。
  - 硬壳可以指定`{"mode":"rigid","bone":"head"}`。其所有细节在UV和材质边界上保持一致。如果不需要独立连接的板或爪子，则可以省略`bone`，按连接的部件选择骨骼。
  - 对于裙子面板组件，使用 `{"mode":"skirt","bone":"root"}`。腰部保持连接。将 `cut` 设置为 `flared`，适用于四链A型裙子；将 `bell` 用于六链裙子，适用于全衬裙或球形礼服；将 `pleated` 用于八链裙子，适用于褶边裙子。每条链都有两个加权关节。为不同的底裙提供单独的项和层次。
  - 对于松散的尾巴，使用 `{"mode":"ribbon","bone":"head","direction":[0,-1,0]}`。将骨骼设置为实际连接点（例如，对于腰部蝴蝶结，使用 `root`）。方向从结指向对齐的Y轴上方的框架中的尖端。分别标记向不同方向延伸的尾巴。最接近结的末端保持在挂载点上，自由端则遵循双关节链结构。
  - 对于悬挂在背部上方的披肩，使用`{"mode":"cape"}`。对于连接在头部的面纱，使用`{"mode":"veil"}`。这些部件在开口处形成三条链，每条链都有自己的枢轴和自由端。对于围裙、开放式外套尾部、袖子装饰或不对称面板，使用`{"mode":"panel","bone":"root","direction":[0,-1,0],"width_axis":[1,0,0]}`。为该单个部件设置连接骨骼、固定边缘方向（`width_axis`）和固定到自由方向。将分割外套的两侧作为独立项目进行标注。将细绳或流苏视为丝带。
- 在**服装项目**上选择`fabric`可以显示悬挂部分的烘焙效果。选择`woven`（默认）、`silk`、`chiffon`、`tulle`、`organza`、`lace`、`satin`、`knit`、`denim`、`wool`、`velvet`或`leather`。预设可以控制延迟时间、摆动增益和最大角度。使用`rigid`表示金属板、硬塑料或扣环。同一种皮革可以制成刚性胸罩、合身上衣或自由型外套面板。该效果代表经过艺术设计的近似效果。检查行走和转向动作中的层叠情况，特别是在下摆和底部。
- 一个代理可以发布一个可重用的装备与结构组合，使用 `charloom mh-garment-preset --library LIB register manifest.json`。使用 `schema` 作为清单格式，`list` 用于发现定义，而 `get ID` 用于检查。通过 `-` 而不是文件名来从标准输入注册。清单可以直接定义数值运动：
  ```json
  {"id":"studio.organza-v1","rig":{"mode":"skirt","cut":{"panels":10}},"fabric":{"delay_s":0.07,"gain":0.48,"max_angle_rad":0.18}}
  ```
  在衣物条目的名称、标签和标注区域之外设置 `"preset":"studio.organza-v1"`。默认从 `guidance.json` 同目录的 `garment-presets/` 读取。共享目录可用 `mh-guide SCAN --out GUIDE --preset-library LIB` 指定，或将顶层 `garment_preset_library` 设为相对于标注文件的路径或绝对路径。向默认目录登记时，将 `--library GUIDE/garment-presets` 传给登记命令。显式填写的 `rig` 和 `fabric` 会各自整体替换预设中的对应字段。迁移会在穿衣网格的 extras 中记录 ID 和解析后的参数。相同定义可重复登记，修改定义时请分配新 ID，使旧标注仍能复现。
- 婚礼礼服的插图示例（将实际图像区域标注在相应位置）：
  ```json
  [
    {"name":"bodice","label":"garment","layer":0,"rig":{"mode":"body"}},
    {"name":"petticoat","label":"garment","layer":1,"fabric":"organza","rig":{"mode":"skirt","cut":"bell"}},
    {"name":"overdress","label":"garment","layer":2,"fabric":"tulle","rig":{"mode":"skirt","cut":"bell"}},
    {"name":"bridal_veil","label":"garment","layer":1,"fabric":"chiffon","rig":{"mode":"veil"}}
  ]
  ```
  使用所选 MakeHuman 模板中的蒙皮骨名。核对 `stage4_garments.rigid_pieces`、`secondary_chains`，并播放穿衣版步行。
- `strokes`（可选）：对于不适合制作多边形的物品，如带子、绳子、胡子或单根线状物，其带状部分应较窄——`{"view": id, "points": [[x,y], [x,y], ...], "width_px": w}`。`points`表示按顺序排列的中心线（一个点=一个点），`width_px`表示物品的可见宽度。带状部分下方的所有内容都是种子和强制性的，因此请将宽度保持为物品本身的宽度。

## 5. `skin`

在明显裸露的皮肤区域（如面部、颈部、手臂、手部和腿部）绘制多边形。这些多边形用于定义皮肤标签，并设定皮肤颜色（将多边形绘制到皮肤边缘；它们像服装多边形一样延伸到皮肤边缘）。`skin_strokes`（可选，形式与服装笔触相同）用于标记薄而裸露的条纹，例如手套和袖子之间的皮肤。任何位于皮肤多边形内的部分都被视为皮肤，其颜色会被复制到身体上。在面部，将多边形绘制在发际线下方几像素处，并远离松散的头发：覆盖眉毛、眼睛、鼻子、脸颊、嘴巴和下巴，但不包括位于太阳穴和脸颊上的细发。皮肤多边形不会将面部前方的裸露毛发视为皮肤（毛发检查会覆盖这一点）；只有服装笔触才会如此处理。

## 6. `skin_cleanup`

裸露皮肤上的多边形，其绘制的纹理不应复制到新身体上：脸颊上绘制的发丝、颈部的衣物阴影、手臂上绘制的带子。如果没有这些元素，则留空。细小的绘制标记可以标记为`skin_cleanup_strokes`（与衣物笔触的形式相同）。

绘制的发丝可能直接留在额头、脸颊或颈部的皮肤贴图上，从发际线开始或延续实际发丝。烘焙可自动清理与头发接触的细暗垂线。在 `3-skin` 渲染里找漏掉的短线、近水平线、未连到头发的线及浅色或偏红的线。在最正对该区域的 `face_*` 或 `head_*` 视图，沿每条线画 `skin_cleanup_strokes`，将 `width_px` 设为线宽再加一两个像素。清理会从邻近皮肤取样，羽化约 4 mm。笔划可穿过眉毛，但眉毛、睫毛、眼线、唇线、雀斑、画上去的胡须或胡茬都应保留。

眉毛（`brow_strokes`，可选；在眉毛被绘制且可见时标记）：在`face_y000`（或正面头部视图）中，每个眉毛画一条线，形式与服装的眉毛线相同：`points`，从眉毛的头部（靠近鼻子）到尾部，沿着眉毛的**中间**部分，曲线上延伸4-6点，`width_px`为眉毛最粗的部分加上2-4像素，因此线条应覆盖整个眉毛及其周围的一小部分皮肤。当一条线穿过眉毛或头发覆盖其尾部时，停止这条线；如果眉毛再次出现，则再画一条线：眉毛线下方被绘制的部分，包括其中的线条。在眉毛线内，皮肤副本会精确复制扫描结果，即使是在被称为眉毛毛发的分割区域也是如此：没有边缘的细线或旁边的线条，没有绘制的线条或异常元素的移除，也没有其他眉毛的镜像；其周围的填充颜色不会采用眉毛的暗色（未标记的情况下，眉毛看起来很薄，断裂，并涂抹在额头上，与边缘相融合）。检查`views/check/face_y000.png`中的紫色条纹：每条条纹都应从头部到尾部覆盖眉毛，其他部分不应有暗色（没有线条，没有眼线，没有发际线）。

## 7. 特写镜头 (`charloom mh-guide-zoom`)

当某个部位在视图中较小或隐藏时——比如眼睛后面的角落、袖口下方的手腕、手指、带子——请要求拍摄特写：

```sh
charloom mh-guide-zoom guidance.json --landmark eye_r_inner
charloom mh-guide-zoom guidance.json --box body_y000 100 500 220 640
```

`--landmark` 以已标记的点为中心，`--box VIEW X0 Y0 X1 Y1` 以某张视图里的像素框为中心。两者都会在 `views/` 和 `views.json` 中新增两个标定视图。`zoom_<name>` 与原视图同向，`zoom_<name>_o30` 向角色对应侧旋转 30°。照常在新视图中标点、画多边形或笔划，用更精确的观测替换同一标记的粗略观测。

## 8. 自检

使用来自仓库根目录的Python命令，结合当前源代码和指南。

```sh
"$PY" scripts/scan-guide.py "$SCAN" --check "$GUIDE/guidance.json"
```

这验证了源文件和图像哈希值，将标记过的像素映射到扫描三角形上，检查所需的传输地标，并输出解析后的JSON数据。检查返回的坐标和标记过的图像。在需要视觉验证时，根据当前指导在已校准的视图中创建叠加层。当前命令将解析后的JSON数据输出到标准输出。旧的`charloom mh-guide-check`界面及其`views/check`图像输出属于已退役的传输实现。

标记那些在校准后像素发生变化的图像。在转移之前，确认解剖学上的左右两侧、每件服装的覆盖范围、关节深度、眼睛开口和嘴唇端点。
